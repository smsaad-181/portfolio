## Motivation

Integrate a DWIN DGUS touchscreen as a local display for sensor readings, controlled entirely from MicroPython on the ESP32 — no C++ firmware required.

## Status

**In progress — unresolved issues.**

The DWIN DGUS display uses a proprietary UART protocol with specific framing (header bytes, address, length, data). DHT11 readings are being acquired correctly, but two issues remain unresolved:

- **UART framing errors** — occasional corrupted frames sent to the display result in missed or garbled screen updates. The exact cause (timing, baud-rate tolerance, or byte-ordering in the MicroPython UART write) has not been pinpointed.
- **ASCII formatting** — the DGUS display expects data in a specific ASCII format for its variable addresses; MicroPython's string encoding is producing off-by-one alignment in some multi-digit values.

Work is ongoing. This entry will be updated once both issues are resolved and the display reliably shows live sensor data.
